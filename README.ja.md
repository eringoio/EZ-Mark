# EZ Mark

[English](README.md) | **日本語**

## OMR スキャナーアプリ

選択式解答用紙の作成・印刷・スキャン・確認を、QR コードによる自動照合と OMR 認識で行えます。

EZ Mark は、テスト（マークシート式・素点採点）とピア評価（匿名評価フォーム）のためのローカルファースト（ローカル完結型）Web アプリケーションです。学生名簿の取り込みから始まり、再利用可能なテンプレートの設計、QR コード付き印刷用 PDF マークシートの生成、回収した用紙のスキャン（PDF/JPG/JPEG/PNG）、あいまいなマークだけを確認するレビューキューによる修正、そして素点・得点率・合否・設問分析・XLSX/CSV 出力までを一括して行います。

## 主な機能

- **テンプレート**: 設問構造・正解表・配点・採点区分を保存する再利用可能な設定。テンプレートから個別の実施を作成します。
- **テスト**: 選択式解答用紙を素点で採点。合格基準点は点数または得点率で任意に設定できます。
- **ピア評価**: 参加者が互いに、評価項目ごとに 1〜5 段階で匿名評価するフォームです。
- **学生名簿の取り込み**: XLSX/CSV に対応し、入力内容を検証・プレビュー表示。重複や競合は取り込み前に目に見える形で検出・解消します。
- **PDF マークシート生成**:
  - 印刷される氏名・学生番号と位置合わせマーカー。
  - QR コードにはランダムな不透明トークンのみを格納し、データベースで照合（個人データは一切含みません）。
  - マーク（バブル）座標は PDF 生成時に保存され、スキャン読み取りはその正確なレイアウトに基づいて行われます。
- **スキャン取り込み**（PDF/JPG/JPEG/PNG）による QR 自動照合。氏名空欄の予備用紙は、取り込み時に学生へ割り当てられます。
- **レビューワークフロー**: あいまい・空欄・複数マーク・未照合のマークだけが確認キューに表示されます。ページ単位の一括確定操作やホットキーにも対応しています。
- **採点**: 素点、得点率、明示的な合格基準点、グループ平均、設問ごとの分析（正答率・空欄数・複数マーク数・確認優先度）。
- **データ出力**: 学生別サマリー、設問ごとの回答一覧、設問分析を XLSX/CSV でダウンロードできます。
- **ピア評価の結果**: 総合ランキング、グループ比較、評価項目別平均、評価対象ごとの内訳。
- **日本語/英語 UI**（ユーザーごとに切り替え可能）。
- **デモモード**: 完全に架空のシードデータを使用し、アップロード/取り込みを無効化。`data-demo/` に独立したストレージを持ちます。
- **ローカルファースト**: SQLite データベース、ローカルディスク上のファイル、クラウドアカウント不要。

## スクリーンショット

_準備中です。_ 本アプリはサーバーレンダリングの Jinja2 + HTMX UI を採用し、ライト/ダークの視覚テーマを備えています。

## アーキテクチャ概要

- **バックエンド**: Python 3 + FastAPI。Jinja2 テンプレートによるサーバーレンダリングと、動的更新のための HTMX。
- **データベース**: SQLAlchemy 経由の SQLite。スキーマバージョン管理付き（`schema_info` バージョンマーカー。互換性のない旧データベースは黙ってアップグレードするのではなく、起動時に拒否されます）。
- **OMR パイプライン**: マーク検出・位置合わせに OpenCV + NumPy、QR 生成に `qrcode` + Pillow、A4 PDF 生成に ReportLab、アップロードされた PDF スキャンのラスタライズに pypdfium2。
- **国際化**: `app/locales/` 配下の JSON ロケール辞書（en/ja）を小型の i18n サービスで提供。
- **ストレージ**: すべて設定されたデータルート配下に配置されます（開発時は `data/`、パッケージ版は `%LOCALAPPDATA%\EZMark` または `EZMARK_ROOT`、デモモードは `data-demo/`）。データベースのレコードは相対パスでファイルを参照します。

本アプリは汎用の OMR テンプレートエディターではなく、制御されたマークシートを自ら生成します。正確なマーク座標マップは PDF 生成時に保存され、スキャン読み取りは同じ座標を参照するため、認識がシンプルで確実になります。

## 動作要件

- Python 3.10 以上（Windows で Python 3.10〜3.13 を検証済み。他のプラットフォーム/バージョンは未検証）
- モダンブラウザー（パッケージ版 Windows アプリモードでは Chrome を使用）
- データベースサーバー不要、外部クラウドサービス不要

## 起動

開発モード（自動リロードの Web サーバー）:

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

ローカル本番風サーバー（リロードなし。`HOST`、`PORT`、`LOG_LEVEL` を読み取ります）:

```bash
python scripts/run_ezmark_server.py
```

その後 `http://127.0.0.1:8000` を開きます。

### デモモード

```bash
set DEMO_MODE=1            # (macOS/Linux では export DEMO_MODE=1)
python scripts/seed_demo.py --reset
python scripts/run_ezmark_server.py
```

デモモードは `data-demo/` ストレージを使用し、架空の名前による 20 問のクイズとピア評価のサンプルをシードし、アップロード/取り込みを無効化します。詳細は [docs/demo-mode.md](docs/demo-mode.md)（英語）を参照してください。

## ローカルファーストのプライバシーモデル

- EZ Mark はあなたのマシン上で動作します。スキャン・名簿・成績・エクスポートがデータルートの外に出ることはありません。
- 外部サービスへの送信は一切行いません。アカウントもテレメトリーもありません。
- 印刷用紙の QR コードにはランダムな不透明トークンのみが含まれ、氏名や学生番号は含まれません。
- ホステッド版は共有デモ用のみの提供であり、個人データのアップロードエンドポイントは無効化されています。
- データの正確な配置場所とクリーンアップについては [docs/data-storage-and-privacy.md](docs/data-storage-and-privacy.md)（英語）を参照してください。

## テストのワークフロー

1. **名簿の取り込み** — 学生を直接貼り付けるか、XLSX/CSV をアップロードします（`student_number`、`name`、`group`）。
2. **テンプレートの作成** — 名称を付けてビルダーを開き、設問構造（連続番号または問題ごとのグループ化）、設問ごとの選択肢の数、配点、任意の採点区分を定義します。
3. **正解表の設定** — 設問ごとに正解を選択します。正解は解答用紙として印刷することもできます。
4. **実施の作成** — テンプレートから実施を作成し、名簿を追加/取り込んで **解答用紙を生成** します。QR トークン付きの印刷用 PDF（任意で予備の空欄用紙も）が作られます。
5. **印刷とスキャン** — 等倍（100%）で印刷し、スキャンを PDF/JPG/JPEG/PNG としてアップロードします。QR 照合は自動で行われ、未照合/空欄ページは後から割り当てられます。
6. **レビュー** — あいまいなマークだけに注意が必要です。各項目を確認または修正し（またはページ単位で一括確定）します。
7. **結果** — 素点・得点率・合否を計算し、グループ平均と設問分析を確認できます。
8. **エクスポート** — 学生別サマリー、設問ごとの回答一覧、設問分析を XLSX/CSV でダウンロードします。

実施設定の各ステップで XLSX/CSV 名簿の取り込みに対応しています。必須ヘッダーは検証され、不足している列・重複した学生番号・競合する行は、黙って取り込まれるのではなく、プレビュー画面で明確にエラー表示されます。

## 対応スキャン形式

- **PDF**（内部で pypdfium2 により 300 DPI でラスタライズ）
- **JPG / JPEG / PNG** 画像

カメラスキャンはサポート対象外です。スキャナーを使用してください（300 DPI 推奨）。

## QR 照合

生成された各用紙には、ランダムな不透明トークンが QR コードとして印字され、データベースに保存されます。アップロードされたスキャンはこのトークンと照合されるため、QR コード内に個人データを印字することなく、用紙と学生を紐付けられます。

## 採点・合格基準点・設問分析

- 各設問には **配点** があります。合計点は正確な合計値です（小数点の配点も許可され、保持されます）。
- **合格基準点** は任意です（素点または得点率で設定）。設定しない場合、結果は中立的な「採点済み」ステータスになります。
- **設問分析** では設問ごとの正答率・空欄数・複数マーク数を一覧化し、どの設問を先に確認すべきかをハイライトします。
- 成績は素点/得点率として報告されます。本ツールは OMR 採点ツールであり、標準化テストの換算スコアエンジンではありません。

## ピア評価

参加者は **評価項目**（スキル）ごとに互いを 1〜5 段階で匿名評価します。テンプレートで評価項目・評価尺度・評価者グループ・1 ページあたりの人数レイアウトを定義します。実施ごとに専用の名簿・評価フォーム PDF・スキャン取り込み・確認キュー・結果（総合ランキング、グループ比較、評価項目別平均）が得られます。レビューでは、あいまい/空欄/無効な評価のみが対象になります。

詳細は [docs/peer-evaluation.md](docs/peer-evaluation.md)（英語）を参照してください。

## デモモード

共有/公開インスタンス向けの専用デモデータセット: `DEMO_MODE=1`、`data-demo/` ストレージ、`scripts/seed_demo.py` によるシード、アップロード/取り込み無効化。詳細は [docs/demo-mode.md](docs/demo-mode.md)（英語）を参照してください。

## ホステッド運用

FastAPI アプリはホストできます（例: `HOST=0.0.0.0 PORT=8000 python scripts/run_ezmark_server.py`）。SQLite は単一ライターのため、ワーカープロセスは **1 つだけ** を実行してください。共有デモにはデモモードを推奨し、データルートを永続化してください。詳細は [docs/hosted-deployment.md](docs/hosted-deployment.md)（英語）を参照してください。

## Windows パッケージ状況

Windows が検証済みプラットフォームです。PyInstaller パッケージのビルド（`ezmark-server.exe` サーバーパッケージと `EZMark` デスクトップランチャー）は `packaging/windows/` 配下にあります。詳細は [docs/windows-packaging.md](docs/windows-packaging.md) および [packaging/windows/README.md](packaging/windows/README.md)（いずれも英語）を参照してください。

## 制限事項

現在の正確な一覧は [docs/limitations.md](docs/limitations.md)（英語）を参照してください。主な内容:

- 汎用の OMR テンプレートデザイナーではないため、解答用紙は EZ Mark が生成するものに限られます。
- 氏名の手書き読み取り、OCR、機械学習によるマーク検出はありません。
- クラウド同期、ユーザーアカウント/ロール（単一オペレーターツール）、公式の標準化テスト採点はありません。
- 日本語 PDF 出力はシステムフォントに依存します（フォントは同梱されません）。
- SQLite は単一ライターのため、ホステッド運用は 1 ワーカーに限られます。
